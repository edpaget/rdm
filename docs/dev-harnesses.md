# Dev harnesses

Regression harnesses for rdm's dogfooding lane, moved verbatim out of `CLAUDE.md` by
`authoring-grammar-and-context-diet` phase 4 (a reference an agent consults occasionally,
not a directive it follows every turn). Cited from `CLAUDE.md`'s `## Dogfooding` section.

- Worktree temp-hygiene harness: `bash scripts/verify-worktree-temp-hygiene.sh` — hermetic regression (~86s) proving no worktree-creating test leaks a worktree into the system temp dir. `worktree::add` places a worktree at `repo_root.parent()/<name>__worktrees/`, so a fixture whose git root IS its `TempDir` puts that sibling where `TempDir::drop` never reaches it — this had accumulated ~44k populated worktrees. Redirects `TMPDIR` at a scratch dir so the count is its own, and carries a planted-mutation self-test (re-root a fixture at its `TempDir`, assert the leak reappears) so the check can never pass vacuously. Run it after touching `worktree_path`/`add` in `rdm-git/src/worktree.rs` or any worktree fixture (`rdm-cli/tests/{cli_worktree,cli_gate,cli_verify}.rs`, `rdm-git/tests/worktree.rs`).
- Git-config isolation harness: `bash scripts/verify-git-config-isolation.sh` — hermetic regression proving the change-review/worktree test suites (`rdm-git/src/{source,worktree}.rs`'s unit tests, `rdm-git/tests/worktree.rs`, and `rdm-cli/tests/{cli_worktree,cli_gate,cli_verify,cli_review_change}.rs`) produce identical results under a clean environment and one seeded with several real settings a developer's `~/.gitconfig` carries (`diff.relative`, `init.defaultBranch`, `advice.detachedHead`, `core.pager`, `commit.gpgsign`) — the shape of the real report behind `2c55784`'s `--no-relative`/`:(top)` fix. Every fixture git call routes through `rdm-git/src/git_test_support.rs` / `rdm-cli/tests/git_test_support.rs` (`git`/`git_with_global`/`write_global_config`), which isolate `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` to `/dev/null` by default with an explicit opt-in for a scenario that wants to inject a specific hostile setting; a planted-mutation self-test strips that isolation and asserts the hostile run diverges. Its final step re-runs `verify-worktree-temp-hygiene.sh` under a milder hostile environment, confirming `c647ab0`'s leak-free guarantee holds there too. Run it after touching either `git_test_support.rs`, any file that includes one of them, or `rdm-git/src/source.rs`'s `unified_diff_argv` guards.
- Session-identity harness: `bash scripts/verify-session-identity.sh` — hermetic multi-process regression for session identity and the changeset journal (`rdm-core/src/session/**`): cross-process stability and inter-session distinctness, rung precedence, stale-lease rejection, journal exactness/disjointness, invisibility to `rdm status` and to a whole-tree commit, measured resolution cost, and (§ K, phase 11) a per-call wrapper-shell continuity section — real `sh -c 'eval …; :'` wrappers under a long-lived non-shell driver — asserting that such a harness fragments, that `rdm commit` exits 0 while naming the cause and the remedy, that the lease set stays bounded with dead-wrapper entries swept, that two concurrent drivers never merge, and that the documented `RDM_HARNESS_SESSION_ID` remedy really yields one changeset; with two planted-mutation self-tests (silence the advisory, remove the create-path sweep). Run it after touching `rdm-core/src/session/**`, the lease creation/GC rule, `GitStore`'s journal wiring, `FsStore::staged_paths`, or the `rdm session` CLI; design record in `docs/session-identity.md`.
- Journal-truncation-race harness: `bash scripts/verify-journal-truncation-race.sh` — hermetic multi-process regression for the changeset journal's truncation-vs-append race: 40 parallel mutations x 6 concurrent commits under one `RDM_SESSION` asserting no authored file is stranded and the journal folds to nothing; a deterministic two-real-process interleave at the `RDM_HARNESS_JOURNAL_BARRIER` seam proving a record appended while a commit is parked survives, including a rewrite of a path that commit is landing; a semantic-empty guard gating the fold, never file absence; and (§ 5) a second deterministic interleave at the `RDM_HARNESS_APPEND_BARRIER` seam running `rdm session gc` — the one non-append operation — from a process sharing neither session id nor lease with a parked appender, proving the sweep is excluded rather than raced (no lease can ever name a rung-1/rung-3 changeset, so gc's liveness check is blind by construction; the parked append holds the kernel-enforced journal lock shared, so the sweep skips rather than rewriting underneath it), and (§ 6) a third interleave at the `RDM_HARNESS_COMPACT_BARRIER` seam covering the other half of that exclusion — a real `rdm session gc` parked after its compare-and-swap and before its `rename`, holding the lock exclusively, while a real `rdm task create` arrives; the append must wait the sweep out and land in the rewritten journal rather than in the inode the rename discards. and (§ 7) a fourth interleave, at the `RDM_HARNESS_JOURNAL_BARRIER` seam again, covering the one writer that used to ignore the protocol outright — `rdm session discard --force`, which destroys a changeset deliberately and did it with a bare `remove_file`; it now retires what it read through `truncate`'s content-keyed tombstone and sweeps the file with `compact`, so a concurrent `rdm task create` keeps its record and still commits. All four sharp sections carry mutant-binary self-tests sharing one build (§ 2b restores the read-modify-write `truncate`, § 5b and § 6b strip the journal lock from both the append and the sweep, § 7b restores the discard's unlink) asserting the loss reappears. Its § 1 asserts the tree is clean immediately after the fan-out with no regeneration step in between — since `retire-generated-index` phase 2 a mutation journals only authored paths, so a dirty path there has exactly one cause, a destroyed append — and § 1b is its deterministic A/B self-test: the same create fan-out racing a commit pinned open at the `RDM_HARNESS_JOURNAL_BARRIER` seam, clean under the fix and stranding every record under the mutant. Run it after touching `record`/`truncate`/`append_line`/`read_journal`/`compact`/`gc_changesets`/`discard_changeset` or the `lock_journal`/`journal_lock_path` helpers in `rdm-core/src/session/journal.rs`, either `journal::truncate` call site in `rdm-store-git` (`commit_changeset_id`, `commit_whole_tree`), the `rdm session gc` sweep, or any of the three barrier seams.
- Scoped-commit harness: `bash scripts/verify-scoped-commit.sh` — hermetic multi-process regression for session-scoped `rdm commit`/`status`/`discard`: disjoint concurrent commits, the same with no session id set, the `Done:` hook path (a distinct section), `init --remote`/the legacy-repo merge-driver sweep/server reconciliation, committed-index reconciliation, scoped discard, and shared reads. Run it after touching `rdm-store-git`'s commit/status/discard paths or those CLI surfaces.
- Lost-update harness: `bash scripts/verify-lost-update.sh` — hermetic multi-process regression for content-digest optimistic concurrency: two real `rdm` processes interleaved at the `RDM_HARNESS_FLUSH_BARRIER` seam (the loser is refused, not silently dropped), a session's own sequential writes never tripping the check, the commit-time `ChangesetPathOverwritten` half, hook-path exit-0 safety, and a planted-mutation rebuild proving the pass is caused by the precondition. Run it after touching `rdm-store-fs`'s baseline/flush machinery, `JournalEntry::digest`, `create_scoped_commit`'s content check, or `rdm_core::paths::describe_path`; the evaluation and carve-outs live in `docs/lost-update-evaluation.md`.
- Rendered-listing observer: `bash scripts/observe-workflow-listing.sh` — NON-hermetic (needs the `claude` CLI): captures the real skill/slash-command listing from a fresh `claude -p` rooted here and asserts the `rdm-wf-` engine-prefix contract against it. Run it deliberately when engine names change; it is not CI-run. Its prior hermetic `--self-test-only` half was retired by the operator amendment to `retire-static-grep-harnesses` (2026-09-23) — it exercised no `claude` CLI, nothing real. See `docs/workflow-schemas.md` § "Observing the rendered listing".
